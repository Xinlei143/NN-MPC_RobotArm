\section{Purpose and evidence boundary}
This supplement provides implementation, configuration, and diagnostic detail
compressed in the conference manuscript. It introduces no results beyond the
frozen or deterministically reanalysed public evidence bundle; its named source
files are listed with SHA-256 digests in \texttt{PUBLIC\_MANIFEST.json}.

All results use MuJoCo position-controlled robot models. ABB IRB~2400 is the
primary robot; UR5e is an independently trained and calibrated nominal
within-robot replication. The evidence does not establish physical-robot
performance, ABB hardware-torque feasibility, hard-real-time scheduling,
robust-MPC guarantees, shared-model transfer, or arbitrary-morphology
generalization. The post-freeze effort sweep is diagnostic only.

The repository implements an optional budgeted uncertainty supervisor for
threaded execution. Model~A alone optimizes CEM; compatible GRU replicas assess
only the selected short-horizon trajectory, and normalized disagreement can
limit residuals or trigger a strict zero-residual fallback to the projected
current IK nominal. It was disabled in all frozen experiments, so no
uncertainty-detection or safety-performance result is reported.

\section{Controller and execution configuration}
The controller is a one-layer GRU (hidden size 256; history length 16) that
predicts velocity increments from aligned $[q_t,\dot q_t,q_t^{\rm ref}]$ tokens,
using one-step increment plus 20-step rollout loss on a disjoint 90/10 split.
Frozen controller cost weights/scales are shared; XML models, data distributions,
checkpoints, normalizers, references, RobotSpec contracts, and delays are
robot-specific. The complete machine-readable contracts are
\url{abb/manifests/control_manifest.json} and
\url{ur5e/manifests/paper.json}.

\paragraph{True-history window validation.}
Held-out model errors use fixed windows beginning at steps 16, 36, \ldots, 176
of each saved 200-step rollout. Every window therefore has a complete
16-token ground-truth recurrent context before its first predicted successor.
Each horizon is evaluated as a separate segmentwise RMSE: $h=1$ measures the
first successor and $h=20$ pools prediction steps $1{:}20$ within each window.
These are not terminal errors. The historical start-of-rollout validation,
which padded the missing initial GRU history, is retained in the evidence
bundle for audit but is not used in the manuscript table.

Residual packets encode corrections, not reusable absolute commands. At packet
age $a$, the full protocol reconstructs and projects
\[
q_t^{\rm cmd}=\Pi_{v,a,\mathcal Q}(\bar q_t^{\rm IK}+r_a+\delta r_t;
q_{t-1}^{\rm cmd},\dot q_{t-1}^{\rm cmd}).
\]
The launch-anchor replay counterfactual instead projects the cached planned
absolute command $q_a^{\rm plan}$. Its large failure is therefore evidence for
the coordinate transformation required by an independently evolving nominal,
not a competitive controller comparison. The implementation is in
\texttt{mpc/delay\_aware\_runner.py}; the protocol definitions are in
\texttt{mpc/delay\_protocol.py}.

\section{Artifacts, references, and calibration}
The manifests record robot contracts, XML/source hashes, command limits, model,
data, and reference hashes, and activation delays. For UR5e, legacy base-run
arguments retain pre-resolution workflow values for fingerprint compatibility;
separate fields record the resolved robot contract and formal per-case delays.
The guard-adjusted 95th-percentile calibration gives ABB $D=6$ and UR5e $D=7$.
Checkpoint and normalizer SHA-256 digests are recorded in the manifests;
artifacts themselves are not committed to avoid distributing large learned
model files through Git.

\paragraph{Model validation and CEM ranking.}
Tables~2--3 provide the principal held-out and replay diagnostics. Complete
window, rollout, and excitation summaries are in
\url{abb/model_validation/aggregate.csv},
\url{abb/model_validation/analysis_manifest.json}, and the corresponding

\url{abb/model_validation/formal_mpc_replay_aggregate.csv} and
\url{claim_evidence/summaries/candidate_ranking.json}. It covers retained,
projection-consistent online candidates only; its lower branch error must not
be compared directly with the broader random-excitation validation.

\paragraph{Robustness and timing.}
ABB robustness applies L3/L6 single-factor payload, actuator-gain, TCP-force,
and observation-noise perturbations. Per-condition/bootstrap results, timing,
packet behavior, and projection activity are in \url{robustness_and_timing} and
\url{abb/summaries}. Primary experiments had no planner failure or imposed
joint, command-velocity, or command-acceleration violation; this does not imply
a physical actuator limit.

\paragraph{Mechanism isolation.}
The frozen 20-case ABB matrix gives $+2.82$ mm for removing future alignment
(95\% CI $[1.27,4.39]$ mm), $+654.60$ mm for launch-anchor absolute replay
($[528.68,778.68]$ mm), and $-0.95$ mm for removing fast feedback
($[-2.25,0.28]$ mm), all relative to FullVirtual. A focused recurrent-history
isolation changed TCP RMSE by $-0.67$ mm with an interval crossing zero. Thus
the evidence supports temporal input consistency but does not establish an
independent nominal tracking gain from recurrent-history advancement. Detailed
projection/task-score and post-freeze effort diagnostics are released in the
corresponding \url{abb/summaries} and \url{claim_evidence/summaries} files;
they did not replace the frozen primary configuration.
